# MetaDrive

A lightweight, multi-tenant, metadata-driven, no-code platform. Tenants install
independent apps built from shared Objects, Fields, Pages, reusable Components
and Flows, all governed by one central RBAC engine (OneEngine). Salesforce-inspired,
without Apex and without Salesforce's size.

Rules for everyone working here, human or AI, are in
[DEVELOPER_POLICY.md](DEVELOPER_POLICY.md) (binding) and [AGENTS.md](AGENTS.md).
The approved roadmap is [docs/METADRIVE_ACTUAL_PLAN.md](docs/METADRIVE_ACTUAL_PLAN.md).

## Current status

Read this before trusting the app.

- The **server** is a new SQL-only runtime (about 1,400 lines). It covers
  authentication, tenant isolation, RBAC, object and field metadata, record CRUD,
  page and component lookup, app installation and a restricted Flow executor.
  See [docs/server-code-organisation.md](docs/server-code-organisation.md).
- The **web app** (about 32,000 lines: Page, Flow, Dashboard and Report builders,
  setup shell, component library) was written against a much larger backend.
- The two are **not at feature parity**. The web app calls 105 distinct API paths
  and the server serves 16 of them. The full list of missing paths is in
  [docs/API_PARITY_GAP.md](docs/API_PARITY_GAP.md), regenerated by
  `npm run audit:api-parity`.
- The server's own documentation says it must not be deployed until a
  non-destructive SQL migration, security checks and end-to-end checks pass.

## Layout

| Path | What it is |
|---|---|
| `apps/server` | Node and Express API on PostgreSQL. Entry: `src/system-files/entrypoint.ts`. Schema: `src/system-files/schema.sql` (new `md_*` tables) |
| `apps/web` | React, Vite and TypeScript front end. Builders live in `src/`, helpers in `src/builders` |
| `docs` | Architecture notes, the roadmap and the API parity report |
| `scripts` | Repository checks (`verify-project-references.mjs`, `verify-pages-artifacts.mjs`, `verify-api-parity.mjs`) |

## Running it

Requires Node 22 and a PostgreSQL database.

```bash
npm ci

# Server (needs DATABASE_URL)
DATABASE_URL=postgres://... PORT=3001 npm run dev:server

# Web (proxies /api to METADRIVE_API_PROXY_TARGET)
npm run dev:web
```

The server defaults to port 10000 but the web dev proxy defaults to
`http://127.0.0.1:3001`, so either run the server with `PORT=3001` as above or
start the web app with `METADRIVE_API_PROXY_TARGET=http://127.0.0.1:10000`.

`schema.sql` creates fresh tables. Do not apply it to a production database that
already holds MetaDrive data.

## Checks

| Command | What it does |
|---|---|
| `npm run test:unit` | Server system tests |
| `npm run build` | Builds web, then server |
| `npm run check` | Project-reference scan, tests, build and lazy-bundle check |
| `npm run audit:api-parity` | Lists web API paths the server does not serve (`--strict` exits 1 if any) |
| `npm run preflight:sql --workspace apps/server` | Read-only inventory of an existing SQL schema |

## Known limitations

Not yet implemented in the server, per its own documentation: migration of
existing data, MFA, field and record sharing policies, the full Flow executor
(get, update and delete records, loops, screen flows, durable restart recovery),
metadata publishing and versioning, and app installation migrations.
